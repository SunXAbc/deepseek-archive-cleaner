# DeepSeek归档删除工具

使用 **Windows 原生界面**的本地归档会话清理工具。查看 DeepSeek Harness 已归档会话的标题、工作目录和占用空间，确认后删除本地会话目录，并同步清理对应归档索引及缓存记录。

**社区独立项目，与 DeepSeek 官方无隶属关系。** 适用于使用 `.dsh` 数据目录及本文所列索引结构的 DeepSeek Harness Windows 客户端；不适用于 DeepSeek 网页版，不处理服务器或云端会话。

## 解决什么问题

归档会话的本地目录仍可能占用磁盘空间。本工具用于已经明确不再需要这些归档记录，希望清理本地副本的场景。

程序只以 `global.archivedSessionIds` 为目标范围，不把所有会话目录视为删除对象。没有归档的会话、其他工作目录和源代码文件不在清理范围内。列表的“工作目录”只用于识别会话，**不会按该列路径删除项目文件**。

## 功能

| 功能 | 具体行为 |
| --- | --- |
| 扫描归档 | 从当前用户 `.dsh` 的归档索引读取会话 ID |
| 标题与目录 | 优先读取本地缓存；缺失时用工作区目录名兜底 |
| 空间统计 | 查询会话目录的文件长度，不读取聊天正文 |
| 批量选择 | 勾选、全选、全不选、反选、双击行切换 |
| 缺失目录识别 | 区分真正的目录缺失与读取失败，可清理残留索引 |
| 定向清理 | 只删除选中的归档目录，并只移除成功项的索引与缓存 |
| 失败保护 | 删除失败项保留索引和缓存，不误报成功 |
| 本地备份 | 删除前备份索引及存在的缓存，备份失败即停止 |
| 原生界面 | 原生按钮、表头、复选框、系统颜色；尺寸按系统 DPI 缩放 |
| 离线运行 | 不上传会话，不联网，不创建默认诊断日志 |

## 使用步骤

1. 在目标客户端中归档需要清理的会话。
2. **完全退出 DeepSeek Harness**，避免数据文件仍被使用。
3. 运行本工具，在 Windows UAC 提示中确认。
4. 核对标题、ID、工作目录、大小和状态，再勾选目标记录。
5. 点击“删除选中”，再次确认数量与大小。
6. 查看结果；如有失败项，解决占用或权限问题后刷新重试。

“刷新”只扫描，不删除。“打开目录”调用系统文件管理器打开本地 `sessions`。没有勾选项时，删除按钮不可用。

若使用另一个管理员账号完成 UAC，当前用户目录可能变化。请用 `-root` 显式指定目标 `.dsh`，操作前核对列表和数据来源。

## 数据来源和兼容范围

默认目录：

```text
%USERPROFILE%\.dsh\
├─ storages\
│  ├─ workspace.json
│  └─ session_projcache.json    # 可选标题、目录缓存
└─ sessions\
   └─ <工作区目录>\
      └─ <session-id>\
```

| 内容 | 使用位置 |
| --- | --- |
| 归档 ID | `workspace.json` → `global.archivedSessionIds` |
| 标题 | `session_projcache.json` → `tables.sessions.<id>.rows.title.val` |
| 工作目录 | `session_projcache.json` → `tables.sessions.<id>.identity.cwd` |
| 大小与时间 | 已归档会话目录的文件长度、目录写入时间 |

索引不匹配、JSON 损坏、ID 不安全、同一 ID 匹配多个目录、路径含联接或符号链接时，程序会报告错误并停止。不会猜测新版客户端的数据结构，也不会把读取失败当成“目录缺失”。

## 删除过程与保护

1. 检查已知的 `DeepSeek Harness.exe` 进程；无法完成检查也会拒绝删除。
2. 重新读取归档状态，校验选中 ID，重新定位唯一的普通本地目录，不信任旧快照的路径。
3. 检查索引与缓存的替换权限，拒绝路径中的符号链接、联接、其他重解析点及网络盘。
4. 在原数据目录保存 `workspace.json.bak`；缓存存在时同时保存 `session_projcache.json.bak`。只保留最近一次操作前的元数据备份。
5. 永久删除选中的会话目录；失败条目保留索引和缓存记录。
6. 核对元数据未被外部程序改写，再移除成功项；每个文件完整写入同目录临时文件并刷新后，才替换原文件。

**不会整份删除缓存。** 未选会话、未归档会话和其他缓存表保留；归档数组以外的索引内容保持原始字节。

**删除不经过回收站，不能撤销。`.bak` 只有索引/缓存，不含会话正文，不能恢复已删除的目录。** 如需完整恢复能力，请先自行备份整个 `.dsh`。

多个目录、索引和缓存不能构成一个完整的文件系统事务。磁盘故障、外部并发写入、删除到一半遇到占用时，可能需要人工处理；失败目录可能已有部分文件被删除。程序会报错并保留元数据备份，不把这种情况报告为完整成功。清理期间不要重新启动 DSH。

## 隐私

- 没有 HTTP 请求、上传、遥测、自动更新或后台服务。
- 不读取浏览器 Cookie、密码、系统凭据或 API Key 配置。
- 统计时只查询属性和长度，不从会话正文中提取聊天内容。
- 标题、工作目录只在本机界面展示。
- 不默认生成日志。元数据备份留在原目录，不会自动发送。
- 备份仍可能包含标题、目录和其他个人元数据，反馈问题时不要附真实缓存或备份。
- 开源材料排除了开发机真实截图、日志、PDB、用户目录及访问令牌。

检查范围和边界见 [PRIVACY.md](PRIVACY.md)。

## 命令行

通常直接双击即可。`-root` 应指向包含 `storages` 和 `sessions` 的数据根目录，而不是 `sessions` 本身。

```powershell
# 默认用户目录，图形界面
& '.\DeepSeek归档删除工具.exe'

# 使用自己准备的数据副本，图形界面
& '.\DeepSeek归档删除工具.exe' -root 'C:\DemoDSH'

# 无界面永久清理指定目录中的全部归档；三个参数缺一不可
& '.\DeepSeek归档删除工具.exe' -root 'C:\DemoDSH' -autodelete -yes
```

无界面模式同样执行进程保护、路径验证和备份。不能省略 `-root` 而直接清理默认目录。它没有交互确认框，只应对已经明确确认的目标使用。

| 退出码 | 含义 |
| --- | --- |
| `0` | 完整成功，或没有需要清理的归档 |
| `1` | 进程保护、读取/备份/写入错误，或存在删除失败项 |
| `2` | 参数错误，或缺少无界面模式的显式根目录/确认参数 |

自动化脚本应等待进程结束并读取退出码。

## 构建源码

安装 Visual Studio 2022 或 Build Tools，并选中：

- 使用 C++ 的桌面开发；
- MSVC v143 x64/x86；
- 适用于 v143 的 C++ MFC（x86 和 x64）；
- Windows 10/11 SDK。

在项目目录执行：


输出：`bin\Release\DeepSeek归档删除工具.exe`，不自动生成压缩包。脚本使用 `vswhere` 定位工具链，不依赖个人安装路径。

测试不以默认 `.dsh` 为目标，不关闭真实 DSH 进程。编译产物、临时夹具和日志不进入 Git。验证细节见 [TESTING.md](TESTING.md)。

## 常见问题

**没有归档记录？** 确认目标客户端使用上述数据结构，并已经归档会话。点击“刷新”；自定义目录使用 `-root`。工具不会猜测其他会话是否应被删除。

**文件被占用？** 完全退出 DSH 后重试。进程保护依据已知文件名判断，改名或新版客户端可能无法自动识别，因此手动退出仍然必要。

**为什么拒绝联接和云占位文件？** 工具以管理员权限运行，必须防止目录被重定向至无关数据。涉及链接、重解析文件和网络盘时，请先准备普通本地数据副本。

**扫描较慢？** 大小统计同步进行，文件很多或存储慢时界面可能暂时等待。扫描不会执行删除，请等待完成并核对列表。

**如何反馈？** 在 [Issues](https://github.com/SunXAbc/deepseek-archive-cleaner/issues) 提供系统版本、复现步骤、错误文字与脱敏的最小虚构样本。不要公开真实会话、个人路径、令牌或完整缓存。
